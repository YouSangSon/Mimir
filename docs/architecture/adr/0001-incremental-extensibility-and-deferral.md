# ADR-0001 — 증분 확장성과 의도적 보류

> **상태**: 채택(Accepted) · 2026-06-13
> **맥락**: S1–S4 완료(122 테스트 · 95% 커버리지 · mypy strict)된 건강한 코드베이스에서 "원래 스코프 이상의 확장·개선·심화"를 진행하라는 요청.
> **현재 보정(2026-06-16)**: 이 ADR은 2026-06-13 당시의 분기 결정을 기록한다. 이후 A4, C1, B1, B2가 증분 구현됐고, B1은 daily pipeline/report scorecard까지 승격됐다. 최신 상태는 [발전 카탈로그](../improvement-catalog.md)를 기준으로 본다.

## 결정

1. **추적 가능성으로 구현 여부를 가른다.** 항목이 *기존 약속*(백로그·로드맵·README)으로 추적되면 구현, 순수 신규면 *설계(spec)*로 남긴다. ([카탈로그 §0](../improvement-catalog.md))
2. **분해하고 순차 진행한다.** 5개 독립 서브시스템을 한 branch에 묶지 않는다. **Increment 1 = 설정 기반 소스 척추(A1)**만 전체 사이클(spec→plan→구현→finish)로 돌린다.
3. **추적 가능한 것만 구현한다(Increment 1):** 설정 기반 시리즈·피드. 빈 설정은 오늘의 기본값을 재현하고, `idempotency_key`·파티션 레이아웃은 불변(테스트로 고정).
4. **신규 고가치 항목은 엄밀한 설계로 남긴다:** 백테스트 하네스(B1), LLM 감성 seam(B2), 타입드 페이로드(A4), 데이터 닥터(C1). 각각 spec 문서를 산출한다.
5. **유료 LLM 호출을 기본값으로 켜지 않는다.** 프로젝트의 *무료(free)* 원칙과 충돌. GRAY 소스와 동일한 off-by-default 토글로 설계만.

## 근거

- 건강한 코드베이스에서 개방형 "개선 찾기"는 스코프 제조기가 되어 YAGNI를 위반한다. 추적성 게이트가 이를 막는다.
- git-as-DB에서 키/파티션의 조용한 변경은 *데이터 손상*이다. "저위험 리팩터"가 고위험이 되는 유일한 경로이므로 불변식을 테스트로 박는다.
- 거대 변경은 리뷰 불가능하다. 증분 + 2단계 리뷰(spec 준수 → 코드 품질)가 품질 게이트를 유지한다.

## 결과

- **장점**: 작고 검증 가능한 변경, 명확한 문서 지도, 데이터 계약 보존.
- **비용**: 가치 높은 항목(백테스트·LLM)이 즉시 코드가 되지 않음 — 그러나 *설계 + 보류 근거*가 "완벽한 문서" 요구를 충족한다.
- **승격 경로**: 각 설계는 사용자가 승인(특히 LLM은 키·비용)하면 자기 plan→구현 사이클로 승격.
