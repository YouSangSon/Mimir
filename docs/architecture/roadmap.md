# Mimir 프로그램 로드맵

> **상태**: 승인됨 (2026-05-31)
> **목적**: 무료·합법으로 수집한 정보에서 투자 인사이트를 길어 올려, 정기적으로(매시간/매일/매주/매월) 텔레그램과 HTML 리포트로 전달한다. 향후 자동매매의 기반이 된다.

Mímir는 북유럽 신화에서 지혜의 샘을 지키는 존재다. 이 프로젝트는 흩어진 공개 데이터를 모아 판단의 재료로 바꾼다.

---

## 1. 제품 원칙

1. **무료(free)** — 상시 서버 없이 GitHub Actions 무료 cron으로 돌리고, 데이터는 repo에 저장한다(git-as-DB).
2. **합법(legal)** — 합법성은 *소스 단위*로 판단한다. 공식 API(SEC EDGAR, DART, FRED, ECOS)를 우선하고, 스크래핑 의존(pykrx)은 ⚠️ 표시·스로틀·내부분석 한정으로 명시 관리한다.
3. **투명한 평가** — 인사이트에는 ⭐별점을 붙이되 근거를 함께 남긴다. 모든 평가에 "투자 권유가 아님" 면책 문구를 포함한다.
4. **분석과 실행의 분리** — Mimir는 *시그널만 발행*한다. 주문 실행은 별도 엔진이 소비한다. 이 경계를 처음부터 긋는다.
5. **점진적 가치 전달** — 각 단계가 끝날 때마다 손에 잡히는 결과가 나온다.

---

## 2. 시스템 분해

요청은 하나의 기능이 아니라 여러 독립 서브시스템이다. 각 서브시스템은 자기만의 `스펙 → 계획 → 구현` 사이클을 가진다. 앞 단계의 출력이 뒤 단계의 입력이 된다.

```
                  ┌─────────────────────────────────────────────┐
                  │  S1. Collector  (데이터 수집 & 저장)          │
                  │  Stooq·EDGAR·pykrx·DART·FRED·ECOS·RSS         │
                  │  → 정규화 JSONL(git-as-DB) + 백필(과거이력)   │
                  └───────────────┬─────────────────────────────┘
                                  │ 원천 데이터 + 누적 이력
                 ┌────────────────┼────────────────────┐
                 ▼                                      ▼
   ┌──────────────────────────┐         ┌──────────────────────────────┐
   │ S2. Analysis & Scoring   │         │ S4. Historical / Event-Analog │
   │ 인사이트 + ⭐별점 모델     │◄────────│ "과거 비슷한 일 → 어떤 종목이  │
   │ (규칙기반 우선, 면책문구) │ 더 풍부 │  올랐/내렸나" (백필 이력 사용) │
   └────────────┬─────────────┘         └──────────────────────────────┘
                │ 점수화된 인사이트
                ▼
   ┌──────────────────────────────────────────┐
   │ S3. Delivery & Reporting                   │
   │ 매시간/매일/매주/매월 텔레그램 다이제스트   │
   │ + 풍부한 일일 HTML 리포트 저장(보관·열람)   │
   └────────────┬───────────────────────────────┘
                │ 시그널 (분석/실행 경계)
                ▼
   ┌──────────────────────────────────────────┐
   │ S5. (미래) Automated Trading               │
   │ 전략엔진 + 증권사 API(페이퍼 먼저) + 리스크 │
   │ Mimir는 시그널만 발행, 실행엔진이 소비       │
   └──────────────────────────────────────────┘
```

## 3. 단계별 스펙

| 스펙 | 만드는 것 | 의존성 | 완료 시 결과물 | 상태 |
|---|---|---|---|---|
| **S1 Collector** | 어댑터 수집기 + JSONL 저장 + 백필 + cron + 최소 가시성 | 없음 | 데이터가 매일 쌓이고 수집 동작을 눈으로 확인 | ✅ 완료 |
| **S2 Analysis** | 지표·시그널 + ⭐별점 + 면책 | S1 데이터 | 별점 달린 인사이트 레코드 | ✅ 완료(규칙기반) |
| **S3 Delivery** | 텔레그램 정기 발송 + 풍부한 HTML 리포트 아카이브 | S2 | 매일 받아보는 리포트/알림 | 🔜 다음 |
| **S4 Historical** | 이벤트 탐지 + 과거 유사사례 매칭 + 사후수익 통계 | S1(+백필) | "과거엔 이랬다" 인사이트 | 상 |
| **S5 Trading** | 전략·체결·리스크 (페이퍼 먼저) | S2/S4 시그널 | (미래) 자동매매 | 상 |

**순서**: S1 → S2 → S3 → S4 → (S5 미래). S1이 과거 이력을 백필하므로 S4는 그 뒤 아무 때나 착수할 수 있다.

---

## 4. 단계별 가치 전달

- **S1 이후** — 데이터가 흐른다. 수집이 동작하는지 눈으로 확인한다.
- **S2 이후** — 별점이 달린 인사이트 레코드가 생긴다.
- **S3 이후** — 사용자가 묘사한 UX(매일 HTML 리포트 + 정기 텔레그램)가 실제로 손에 들어온다.
- **S4 이후** — 리포트가 "과거 유사 사례" 인사이트를 더한다.
- **S5(미래)** — 시그널을 실제 주문으로 연결한다.

---

## 5. 횡단 관심사 (모든 스펙에 적용)

- **스케줄링** — 별도 스펙이 아니다. cadence 오케스트레이터를 S1에서 세우고, 각 스펙이 자기 워크플로를 추가한다.
- **문서화** — 스펙마다 설계문서(`docs/superpowers/specs/`)와 사용자 문서를 남긴다.
- **테스트** — TDD, 커버리지 80%+ (단위·통합·E2E).
- **시크릿** — API 키·봇 토큰은 GitHub Actions Secrets로만 관리하고 절대 커밋하지 않는다.
- **합법성 레지스트리** — 소스마다 `legal_status`와 `rate_limit`을 메타데이터로 들고 코드로 강제한다.
- **면책** — 모든 인사이트·평가에 "투자 권유가 아님"을 명시한다.

---

## 6. 자동매매(S5) seam

지금 만들지 않는다. 그러나 경계는 지금 긋는다.

- S2/S4는 구조화된 **시그널 레코드**를 발행한다(종목, 방향, 확신도/별점, 근거, 타임스탬프).
- 미래의 실행 엔진은 이 시그널을 *읽기 전용*으로 소비한다. 분석 코드는 주문 API를 절대 직접 호출하지 않는다.
- 이 분리 덕에 분석 버그가 곧장 주문으로 이어지지 않고, 페이퍼 트레이딩으로 안전하게 검증한 뒤 실거래로 승격할 수 있다.
